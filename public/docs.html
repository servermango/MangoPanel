Overview

Introduction

MangoPanel is a lightweight, self-hosted, hPanel-style shared hosting control panel. It provides a complete web hosting control plane designed for real account stacks, queued jobs, DNS management, SSL certificates, email services, databases, file managers, and backups.

Core Philosophy

MangoPanel uses a zero-external-framework Python HTTP API backed by SQLite WAL mode. Desired infrastructure state is written to SQLite, while a dedicated local Node Agent processes privileged operations asynchronously.

Key Platform Highlights

  • Account Isolation: One dedicated Docker Compose stack per customer account (OpenLiteSpeed, MariaDB, phpMyAdmin, Filebrowser, SFTP, Mail).
  • Audited Control Plane: Single SQLite database (`mangopanel.sqlite3`) tracking users, websites, databases, mailboxes, and job logs.
  • Built-in Security: Signed JWT session tokens, mandatory TOTP multi-factor authentication, and short-lived launch tokens for sub-services.
  • Dual-Port Panel Architecture: Separate listening ports for Client (`8000`) and Admin (`8001`) to isolate administrative API routes.

Setup

Installation

Choose one of the following methods to install MangoPanel on your host system.

Option A: Automated One-Line Install (Recommended)

Fresh clone and auto-installation using `git`:

git clone https://github.com/servermango/MangoPanel.git MangoPanel && cd MangoPanel && bash scripts/install.sh

Option B: Archive Install (If Git is unavailable)

mkdir MangoPanel && curl -fsSL https://codeload.github.com/servermango/MangoPanel/tar.gz/refs/heads/main | tar -xz -C MangoPanel --strip-components=1 && cd MangoPanel && bash scripts/install.sh

Option C: Manual Makefile Step-by-Step

cd MangoPanel

# 1. Install system prerequisites, Python venv, Docker tools & pre-pull images
make install

# 2. Check Python, Docker, and listening ports
make dev-init

# 3. Start the client and admin panel services (seeds dev data on first run)
make dev-up

Guide

Basic Setup

Follow these steps to configure your initial administrative credentials, define hosting plans, and provision your first customer accounts.

1. Admin Setup & Recovery

When starting MangoPanel on a fresh database with zero admins, visiting `http://:8001/admin` automatically routes to the First-Admin Setup Page (`/admin/setup`).

  • Fill in the admin email address and password.
  • The system generates an initial TOTP authenticator secret and displays an `otpauth://` QR code.
  • Scan the QR code in Google Authenticator / 1Password and verify a code before completing setup.
  • Once an admin exists, public first-admin setup is permanently locked.

CLI Admin Recovery Tool

If an administrator loses password or 2FA access, run `scripts/admin_recovery.py` directly on the server host:

# Reset admin password
sudo python3 scripts/admin_recovery.py --email admin@example.com --set-password

# Generate new TOTP secret & display QR setup URI
sudo python3 scripts/admin_recovery.py --email admin@example.com --enable-totp

# Disable TOTP requirement for emergency login
sudo python3 scripts/admin_recovery.py --email admin@example.com --disable-totp

2. Creating Hosting Plans

Before customer accounts can be provisioned, define at least one active Hosting Plan in the Admin Panel under Plans (`/admin#plans`).

Plan Field Description Example Value
Name & Slug Human readable label and identifier `Starter Plan` (`starter`)
CPU & RAM Limit Per-account container execution limits `1.0 CPU` / `512 MB RAM`
Storage & Inodes Disk quota in MB and file count limit `10000 MB` / `250000 inodes`
Website Count Maximum allowed hosted domains `5 websites`
Databases & Mailboxes Max MySQL/PostgreSQL DBs and email accounts `5 DBs` / `10 mailboxes`
DNS Policy DNS provider selection (Local PowerDNS / Cloudflare) `Cloudflare Managed`

3. Provisioning Customer Clients

Customer accounts can be created through two primary workflows:

Workflow A: Self-Service Signup Page (`/signup`)

  1. User visits `http://:8000/signup`.
  2. Enters email, password, and selects an available hosting plan.
  3. API executes `POST /api/public/signup`, generates customer credentials, sets up 2FA, and assigns an account ID (e.g., `u000001`).

Workflow B: Admin Dashboard Provisioning

  1. Admin opens Admin Panel > Clients.
  2. Clicks Create Client Account.
  3. Enters user email, password, and selects the hosting plan.
  4. The system creates the user, generates account directory structure under `user_files/accounts//`, and queues container deployment.

Domain & Subdomain DNS Setup

To instruct users to set up a server domain or subdomain for MangoPanel and tool access, create DNS A-records pointing to your server's IP address.

Domain Setup Example

For example, if you want your users to reach the panel from hosting.servermango.com, create the following DNS A-records pointing to your server's public IP address:

Type Name / Host Target / Value Purpose
A hosting.servermango.com (or @) <SERVER_IP> Main panel and web traffic
A *.files.hosting.servermango.com (or *.files) <SERVER_IP> Per-account Filebrowser tool subdomain routing

Once configured, access MangoPanel at:

  • Admin Panel: http://hosting.servermango.com:8001/admin
  • Client Panel: http://hosting.servermango.com:8000/client (or http://hosting.servermango.com:8000/)

Maintenance

Server Migration

Because all database state and customer files live inside `user_files/`, migration to a new server takes 5 simple steps:

  1. Stop Services: bash scripts/service mangopanel stop on old server.
  2. Install on New Server: Run installation script on destination machine.
  3. Transfer `user_files/`: rsync -avzP /path/to/old/user_files/ root@new-server:/path/to/new/user_files/
  4. Start Services & Provision Stacks: bash scripts/service mangopanel start & run agent stack rebuild.
  5. Update DNS: Point A-records to the new server IP.

Admin Panel

Admin Panel Documentation

The Admin Panel is the control surface for platform operators. It manages customers, hosting accounts, plans, DNS providers, infrastructure jobs, security settings, and system health. Administrative actions are audited and privileged changes require administrator permissions.

Production safety

Administrative changes can affect live customer traffic. Review the target client and hosting account before applying a change, and use Hard suspend only when taking the entire account stack offline is intentional.

1. Admin Access & Security

Open the Admin Panel at /admin on the administrative panel port. Admin sessions use signed, short-lived tokens and two-factor authentication when configured.

Administrator roles and permissions

  • Authentication: Sign in with the administrator email, password, and authenticator code.
  • Permissions: Scope checks protect client, plan, system, DNS, incident, and administrator-management operations.
  • Session revocation: Password, email, or 2FA changes invalidate existing sensitive sessions.
  • Audit trail: Account, profile, suspension, security, and infrastructure actions are recorded in the audit log.

Recommended security routine

  1. Use a unique administrator password stored in a password manager.
  2. Keep administrator TOTP enabled and store recovery material offline.
  3. Use the minimum administrator permission set required for each operator.
  4. Review audit entries after account status, password, or 2FA changes.

2. Dashboard & System Monitoring

The Admin Dashboard summarizes customer count, hosting accounts, resource use, jobs, incidents, and service health.

What to inspect first

  • System status: Check service availability and active maintenance notices.
  • Jobs: Review queued, running, failed, and retried agent jobs.
  • Storage: Check disk and inode pressure before provisioning or rebuilding stacks.
  • Network and nodes: Confirm nodes are online before starting account operations.

Queued operations

Most infrastructure changes are represented as jobs. The API records the requested state first, then the local agent applies files, container changes, and service configuration. A failed job should be investigated before retrying it.

3. Client Profiles, Billing & Identity

Use Clients > Edit Profile to manage a customer identity without exposing stored secrets.

Editable profile data

  • Full name and login email.
  • Billing email, company, phone, tax ID, and postal address.
  • Account status where the operator has the required permission.

Password and 2FA controls

Administrators can reset a client password or enable, disable, and rotate client 2FA. Sensitive actions require administrator re-authentication and invalidate the client’s active browser sessions.

4. Hosting Accounts & Stack Lifecycle

A hosting account represents an isolated customer stack, account directory, websites, databases, mail services, and generated runtime configuration.

Account states

StateMeaningTypical next action
provisioningInitial files and services are being prepared.Wait for the provisioning job.
activeNormal customer operation.Manage plan, domains, services, or access.
suspendedSoft suspended; web traffic is gated while the stack remains available.Unsuspend or escalate to Hard suspend.
hard_suspendedEntire account stack is stopped and web traffic is gated.Unsuspend after the operational issue is resolved.
rebuildingGenerated configuration or stack services are being reapplied.Monitor the associated job.

5. Soft Suspend and Hard Suspend

MangoPanel provides two deliberate suspension levels. Both are account-level controls and both show a suspension message to the customer in the User Panel.

Soft suspend

Soft suspend is the normal access restriction. It changes the hosting account state to suspended and creates a filesystem marker. The web server checks that marker and serves the MangoPanel “Account Temporarily Unavailable” page instead of the customer’s website.

  • The account’s containers remain running.
  • Web requests are blocked at the document-root serving layer.
  • The marker is checked from the filesystem, so normal web traffic does not query SQLite.
  • Customer write operations are rejected by the panel while the account is suspended.
  • Use this when access should be restricted without stopping mail, database, or other stack services.

Hard suspend

Hard suspend is an operational shutdown. It changes the state to hard_suspended, keeps the filesystem serving gate active, and queues a job that runs docker compose down --remove-orphans for the account’s complete stack.

  • The web, database, mail, Filebrowser, SFTP, cache, cron, and related account services are stopped.
  • Existing account data and persistent volumes are retained; Hard suspend is not account deletion.
  • The User Panel remains available for the customer to see the suspension notice, but account operations are restricted.
  • Use this for severe abuse, non-payment escalation, incident containment, or a deliberate full shutdown.

How suspension is applied

  1. The Admin Panel writes the suspension state and creates the account marker immediately.
  2. Domain document roots receive a filesystem marker and a managed web-server gate.
  3. An agent job records the operation and applies the stack action.
  4. Failed jobs leave the account fail-closed and remain visible for investigation and retry.
  5. The public website returns the suspension page without loading WordPress or another customer application.

When to choose each option

SituationRecommended actionReason
Temporary billing or policy holdSoft suspendRestricts access while keeping services available for controlled recovery.
Abuse investigation or active web compromiseHard suspendStops the complete account stack and limits further activity.
Planned maintenance requiring service downtimeHard suspendProvides a known stopped state before maintenance.
Account deletionUse the deletion workflowSuspension never deletes customer files or persistent data.

6. Unsuspend and Account Recovery

Click Unsuspend after the reason for the hold has been resolved. For a soft suspension, the serving marker is removed after the account state is restored. For a hard suspension, the agent first brings the account stack back up and then clears the marker.

Recovery checklist

  1. Confirm the customer, account username, and suspension reason.
  2. Review failed jobs, audit entries, and relevant security or billing notes.
  3. For Hard suspend, verify node capacity and Docker availability.
  4. Click Unsuspend and monitor the resulting agent job.
  5. Verify the website, database, mail, and Filebrowser routes after recovery.
Fail-closed recovery

If the stack cannot be started, the account remains restricted instead of being marked fully active while services are unavailable. Investigate the job error and retry only after correcting the cause.

7. Plans, Domains, DNS & SSL

Plans define CPU, memory, storage, inode, website, database, mailbox, backup, and DNS policy limits. Domain and DNS tools apply records, nameserver assignments, provider migrations, and verification jobs. SSL issuance is tracked per website and normally runs asynchronously through the agent.

Safe change order

  1. Update or validate the plan limits.
  2. Confirm the target account and current resource use.
  3. Apply the plan or DNS change.
  4. Watch the job result and verify the generated stack or DNS state.

8. Audit, Jobs & Maintenance

Use the audit and job views to answer who changed what, when it changed, which account was affected, and whether the agent completed the requested operation. Keep failed jobs until their cause and recovery are documented.

  • Use job retry for transient infrastructure failures only.
  • Use storage and quota views before large migrations or rebuilds.
  • Use incident status tools to communicate platform-wide maintenance separately from account suspension.
  • Do not manually delete account markers, compose files, or runtime directories as a substitute for the panel workflow.
User Panel

User Panel Documentation

The User Panel is the customer workspace for managing websites, domains, DNS, databases, mailboxes, files, backups, deployments, security, and account settings. Customers can manage only the hosting accounts and collaborator scopes assigned to them.

1. Sign-in, 2FA & Session Security

Open the Client Portal at /client or the configured client-panel URL. Sign-in may require a TOTP authenticator code after the password is accepted.

  • Use Sign out when leaving a shared or administrative workstation.
  • Changing the email, password, or 2FA settings requires sensitive-change verification.
  • Changing a password or login email revokes existing sessions and requires a fresh login.
  • Never share an API token or authenticator secret with support staff or collaborators.

2. Dashboard & Account Selection

The dashboard displays the selected hosting account, websites, resource summaries, warnings, and recent account activity.

Multiple accounts

If you own multiple accounts or have collaborator access, use the account selector to switch the active scope. The selected account controls which websites, databases, files, mailboxes, and tools are displayed.

Resource summary

Disk, inode, CPU, and memory summaries are estimates based on the latest usage sample. A high value may require cleanup, a plan change, or administrator assistance.

3. Account Settings, Billing & Identity

Account Settings contains your identity and billing profile. You can update your name, billing email, company, phone, tax information, and address.

Password and 2FA

  • Use a long, unique password and confirm the current password before changing it.
  • Keep TOTP enabled for accounts that manage production websites or email.
  • Disabling or rotating 2FA requires current security verification and may sign you out.

4. Websites, Domains & File Manager

Websites

Create websites by selecting a domain, document root, and PHP version. The platform generates an isolated web-server virtual host for each website.

Domains and DNS

Use the Domains and DNS tools to inspect nameservers, manage permitted DNS records, verify propagation, and select the available DNS provider. DNS changes can take time to propagate outside MangoPanel.

DNS Zone Editor: Rebuild vs Verify

DNS record changes normally queue a provider sync automatically. The two action buttons serve different purposes:

Action What it does When to use it Does it change DNS?
Rebuild Reads the records saved in MangoPanel, rebuilds the authoritative zone, and publishes it to the selected provider. After a failed sync, provider change, imported-record cleanup, or when you need to republish the current saved zone. Yes. It queues a DNS synchronization job.
Verify Performs a read-only public DNS check and compares the domain’s observed nameservers with the provider’s expected nameservers. After changing nameservers at the registrar, or when confirming that delegation has propagated. No. It does not edit records or nameservers.

Recommended workflow

  1. Edit or add the DNS record. MangoPanel queues synchronization automatically.
  2. Use Rebuild only if you need to republish the saved zone or a sync failed.
  3. Copy the provider nameservers shown by MangoPanel into your registrar when using an authoritative provider such as Cloudflare.
  4. Wait for delegation to propagate, then click Verify.

DNS status meanings

  • Published / Active: The provider accepted the zone.
  • Pending nameserver: The zone was published, but public delegation has not yet been confirmed.
  • Provider failed: The provider rejected the operation or could not be reached. Read the displayed error, correct the provider/account or record issue, then use Rebuild.
  • DNS sync in progress: A queued job is currently applying the saved zone. Avoid repeated rebuilds until it finishes.

Switching the provider

Use Switch DNS Provider to open the domain-scoped provider modal. The available providers and Cloudflare accounts come from the hosting plan. If multiple Cloudflare accounts are permitted, choose the account for that domain in the modal; changing it does not change other domains in the account.

File Manager

Use Access all files of domain for a domain-scoped file view. Use Access Root Filesystem of this hosting for account-level directories when your account permissions allow it. File edits are sent through the authenticated Filebrowser proxy; do not expose or reuse launch URLs.

File safety

Editing wp-config.php, server rules, or application configuration can take a website offline. Download a backup or copy the original content before making changes.

5. Databases & Database Users

The User Panel supports MySQL and PostgreSQL database records, users, grants, and password changes subject to plan limits.

  • Create database names and users using the panel-generated account scope.
  • Grant only the privileges required by the application.
  • Store database credentials in the application’s secure configuration rather than in public files.
  • Use phpMyAdmin or Adminer only through their authenticated account launch path.

6. Mailboxes, Routing & Webmail

Create mailboxes, aliases, forwarders, and autoresponders under the active account. Mailbox quotas and daily sending limits are enforced by the hosting plan.

Deliverability checklist

  • Publish the required SPF, DKIM, and DMARC records for each sending domain.
  • Use a valid mailbox password and avoid reusing the panel password.
  • Check DNS status before troubleshooting remote delivery.

7. Backups, Git & SSL

Backups and restores

Create backups before application upgrades or bulk file changes. Restores can overwrite current files and should be treated as a planned operation.

Git deployments

Configure a repository, branch, and deployment path, then use the deployment history to inspect commits and roll back when supported.

SSL

Issue or inspect SSL certificates from the website security tools. Confirm DNS points to the correct server before requesting a certificate.

8. Collaborators & Account Switching

Account owners can invite collaborators and assign scoped permissions. A collaborator may be restricted to selected websites or tools.

  • Switch accounts before performing an operation intended for another hosting account.
  • Confirm the active username in the panel header before opening files or databases.
  • Collaborator permissions are enforced by account and website scope, including Filebrowser paths.
  • Revoke access when a collaborator no longer needs it.

9. Suspended Hosting Accounts

When an administrator suspends the selected hosting account, the User Panel displays a clear suspension message. The panel remains available for account information and support communication, but hosting operations that modify the suspended account are blocked.

Soft suspension

Websites show the temporary-unavailability page while the account’s services remain running. You cannot use suspended-account operations to bypass the hold.

Hard suspension

The account’s complete hosting stack is turned off. Websites, databases, mail, Filebrowser, SFTP, and scheduled account services remain unavailable until an administrator unsuspends the account and the stack starts successfully.

What to do

  1. Review the suspension notice in the User Panel.
  2. Contact the hosting administrator or support channel listed by your provider.
  3. Do not delete account files or attempt to change application configuration to work around the suspension.
  4. After administrator recovery, refresh the panel and verify the affected website and services.

10. API Tokens & Troubleshooting

API tokens are created under Account Settings and should be granted only the permissions required by an integration. Treat tokens like passwords, rotate them after suspected exposure, and revoke unused tokens.

Common issues

  • Website unavailable: Check the dashboard warning, DNS nameservers, SSL status, and whether the account is suspended.
  • File Manager login screen: Reopen the tool from the User Panel so a fresh account-scoped launch token is generated.
  • Access denied: Confirm the active account and collaborator permissions.
  • Changes still processing: Check activity and job status before repeating the operation.
Developer API

Client Area API Reference & Parameters

MangoPanel provides a clean REST API for managing websites, DNS records, databases, mailboxes, cron jobs, files, SSL, and monitoring resource usage using API keys or Bearer JWT tokens.

1. Authentication & Headers

Client panel users can generate API keys under Account Settings > API Tokens inside the Client Area (port 8000). Generated tokens have the prefix mp_ (e.g., mp_a1b2c3d4...).

# Option A: Bearer Header (Recommended)

# Option B: Custom Header
X-API-Key: mp_YOUR_API_KEY

# Option C: Query Parameter

# Optional Account Scope Switcher Header (for multi-account users)
X-Hosting-Account-ID: 2

Admin Area API Documentation

The Admin Area API provides full administrative control over MangoPanel, including client provisioning, hosting plan configuration, cluster node registration, DNS settings, incident management, storage cleanup, and system audit logs.

Authentication & Granular Permission Scopes

Authenticate requests by passing an Admin API Token or session JWT in the Authorization header:
Authorization: Bearer mp_admin_1a2b3c4d...

Admin API Tokens support granular permission scopes to restrict API capabilities. The available scopes are:

Permission Scope Access Rights
* Full Superadmin privileges across all administrative endpoints.
clients.manage Manage client accounts, hosting accounts, and hosting plans.
hosting.manage Manage cluster nodes, account container stacks, and server infrastructure.
dns.manage Manage DNS providers (PowerDNS/Cloudflare), domain assignments, and registrars.
system.manage Manage platform health status, incidents, storage cleanup, default page, and audit logs.
admins.manage Manage administrative users, admin passwords, and Admin API Tokens.

Reseller API

Reseller Area API Documentation

The Reseller Area API provides full programmatic control over sub-client accounts, custom sub-plan creation, hosting stack provisioning, storage quota monitoring, and API key management on Port 8002.

Authentication & Reseller Key Scope

Authenticate requests by passing a Reseller API Token or Reseller Session JWT in the Authorization header:
Authorization: Bearer mp_reseller_1a2b3c4d...

Reseller API endpoints are served on Port 8002 and automatically enforce the reseller's master package limits. Sub-plan limits and aggregate storage allocations are validated in real time against master plan caps.

Enforcement Rule System Behavior
Package Limit Capping When creating a custom sub-plan (POST /api/reseller/plans), RAM, storage, max websites, and max databases cannot exceed the master reseller plan's package limits.
Aggregate Storage Cap When provisioning hosting stacks for sub-clients (POST /api/reseller/hosting-accounts), the total allocated storage across all sub-accounts cannot exceed the master reseller plan's total storage capacity.
Max Sub-Clients & Sub-Plans Sub-client creation and sub-plan creation enforce max_clients and max_reseller_subplans boundaries specified by the administrator on the master reseller plan.
