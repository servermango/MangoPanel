Overview

Introduction

MangoPanel is a lightweight, self-hosted, hPanel-style shared hosting control panel. It provides a complete web hosting control plane designed for real account stacks, queued jobs, DNS management, SSL certificates, email services, databases, file managers, and backups.

Core Philosophy

MangoPanel uses a zero-external-framework Python HTTP API backed by SQLite WAL mode. Desired infrastructure state is written to SQLite, while a dedicated local Node Agent processes privileged operations asynchronously.

Key Platform Highlights

  • Account Isolation: One dedicated Docker Compose stack per customer account (OpenLiteSpeed, MariaDB, phpMyAdmin, Filebrowser, SFTP, Mail).
  • Audited Control Plane: Single SQLite database (`mangopanel.sqlite3`) tracking users, websites, databases, mailboxes, and job logs.
  • Built-in Security: Signed JWT session tokens, mandatory TOTP multi-factor authentication, and short-lived launch tokens for sub-services.
  • Dual-Port Panel Architecture: Separate listening ports for Client (`8000`) and Admin (`8001`) to isolate administrative API routes.

Setup

Installation

Choose one of the following methods to install MangoPanel on your host system.

Option A: Automated One-Line Install (Recommended)

Fresh clone and auto-installation using `git`:

git clone https://github.com/servermango/MangoPanel.git MangoPanel && cd MangoPanel && bash scripts/install.sh

Option B: Archive Install (If Git is unavailable)

mkdir MangoPanel && curl -fsSL https://codeload.github.com/servermango/MangoPanel/tar.gz/refs/heads/main | tar -xz -C MangoPanel --strip-components=1 && cd MangoPanel && bash scripts/install.sh

Option C: Manual Makefile Step-by-Step

cd MangoPanel

# 1. Install system prerequisites, Python venv, Docker tools & pre-pull images
make install

# 2. Check Python, Docker, and listening ports
make dev-init

# 3. Start the client and admin panel services (seeds dev data on first run)
make dev-up

Guide

Basic Setup

Follow these steps to configure your initial administrative credentials, define hosting plans, and provision your first customer accounts.

1. Admin Setup & Recovery

When starting MangoPanel on a fresh database with zero admins, visiting `http://:8001/admin` automatically routes to the First-Admin Setup Page (`/admin/setup`).

  • Fill in the admin email address and password.
  • The system generates an initial TOTP authenticator secret and displays an `otpauth://` QR code.
  • Scan the QR code in Google Authenticator / 1Password and verify a code before completing setup.
  • Once an admin exists, public first-admin setup is permanently locked.

CLI Admin Recovery Tool

If an administrator loses password or 2FA access, run `scripts/admin_recovery.py` directly on the server host:

# Reset admin password
sudo python3 scripts/admin_recovery.py --email admin@example.com --set-password

# Generate new TOTP secret & display QR setup URI
sudo python3 scripts/admin_recovery.py --email admin@example.com --enable-totp

# Disable TOTP requirement for emergency login
sudo python3 scripts/admin_recovery.py --email admin@example.com --disable-totp

2. Creating Hosting Plans

Before customer accounts can be provisioned, define at least one active Hosting Plan in the Admin Panel under Plans (`/admin#plans`).

Plan Field Description Example Value
Name & Slug Human readable label and identifier `Starter Plan` (`starter`)
CPU & RAM Limit Per-account container execution limits `1.0 CPU` / `512 MB RAM`
Storage & Inodes Disk quota in MB and file count limit `10000 MB` / `250000 inodes`
Website Count Maximum allowed hosted domains `5 websites`
Databases & Mailboxes Max MySQL/PostgreSQL DBs and email accounts `5 DBs` / `10 mailboxes`
DNS Policy DNS provider selection (Local PowerDNS / Cloudflare) `Cloudflare Managed`

3. Provisioning Customer Clients

Customer accounts can be created through two primary workflows:

Workflow A: Self-Service Signup Page (`/signup`)

  1. User visits `http://:8000/signup`.
  2. Enters email, password, and selects an available hosting plan.
  3. API executes `POST /api/public/signup`, generates customer credentials, sets up 2FA, and assigns an account ID (e.g., `u000001`).

Workflow B: Admin Dashboard Provisioning

  1. Admin opens Admin Panel > Clients.
  2. Clicks Create Client Account.
  3. Enters user email, password, and selects the hosting plan.
  4. The system creates the user, generates account directory structure under `user_files/accounts//`, and queues container deployment.
DNS Integration

Cloudflare as DNS - Setup Instructions

MangoPanel supports Cloudflare as an authoritative DNS provider for managed domains. Configure Cloudflare credentials in the Admin panel under DNS Settings.

Cloudflare API Prerequisites

  • Account ID: Found in the right sidebar of the Cloudflare Dashboard on any domain's Overview page.
  • API Token: Generated under My Profile > API Tokens in Cloudflare.
Required Token Permissions

The Cloudflare API Token must include these explicit permissions:
• Zone > Zone > Edit
• Zone > DNS > Edit

DNS Routing

Domain & Subdomain DNS Setup

To instruct users to set up a server domain or subdomain for MangoPanel and tool access, create DNS A-records pointing to your server's IP address.

Domain Setup Example

For example, if you want your users to reach the panel from hosting.servermango.com, create the following DNS A-records pointing to your server's public IP address:

Type Name / Host Target / Value Purpose
A hosting.servermango.com (or @) <SERVER_IP> Main panel and web traffic
A *.files.hosting.servermango.com (or *.files) <SERVER_IP> Per-account Filebrowser tool subdomain routing

Once configured, access MangoPanel at:

  • Admin Panel: http://hosting.servermango.com:8001/admin
  • Client Panel: http://hosting.servermango.com:8000/client (or http://hosting.servermango.com:8000/)
Architecture

Current Build Features

  • Python standard-library HTTP API with zero framework overhead.
  • SQLite WAL-mode schema with versioned development seed data.
  • Public client signup (`/signup`), client portal (`/`), admin panel (`/admin`), and status page (`/status`).
  • Full coverage for websites, MySQL, PostgreSQL, mailboxes, SFTP, cron jobs, backups, Git deployments, and audit logs.
  • Node-agent job runner with simulated and Docker Compose execution modes.
  • Account-stack generator for OpenLiteSpeed, Filebrowser, phpMyAdmin, MariaDB, cron, SFTP, and shared mail scaffolding.

Data Layout

All persistent control-plane state and customer hosting data lives under user_files/:

user_files/
  accounts/                 # per-customer hosting files  (MP_ACCOUNT_ROOT)
    u000001/
      account.json
      domains/<domain>/public_html/
      databases/  mail/  backups/  ssl/  git/  .runtime/
  data/                     # control-plane database       (MP_DATA_DIR)
    mangopanel.sqlite3
Maintenance

Server Migration

Because all database state and customer files live inside `user_files/`, migration to a new server takes 5 simple steps:

  1. Stop Services: bash scripts/service mangopanel stop on old server.
  2. Install on New Server: Run installation script on destination machine.
  3. Transfer `user_files/`: rsync -avzP /path/to/old/user_files/ root@new-server:/path/to/new/user_files/
  4. Start Services & Provision Stacks: bash scripts/service mangopanel start & run agent stack rebuild.
  5. Update DNS: Point A-records to the new server IP.

Developer API

Client Area API Reference & Parameters

MangoPanel provides a clean REST API for managing websites, DNS records, databases, mailboxes, cron jobs, files, SSL, and monitoring resource usage using API keys or Bearer JWT tokens.

1. API Key Guide — Client Panel

How to Generate a Client API Key

Client API keys are scoped to a hosting account, not just a user. There are two ways to create one:

  • In the UI: Log in to the Client Area (port 8000), go to Account Settings > API Tokens, click Generate Token, and enter a descriptive name.
  • Via API (authenticated session or existing token): 
    POST /api/client/api-tokens
Content-Type: application/json
Authorization: Bearer mp_EXISTING_TOKEN

{"name": "My Automation Key"}
    Response: 
    {"id": 3, "name": "My Automation Key", "token": "mp_a1b2c3d4e5f6..."}
Plan Requirement: API Access Must Be Enabled

Client API tokens will be rejected at authentication time with 403 api_access_disabled_for_plan unless the hosting account's plan has API Access enabled (allow_api_access = true). An admin must enable this flag on the plan. The API also blocks token creation at POST /api/client/api-tokens if the plan flag is off.

Token Format

Client tokens are prefixed with mp_ (without admin or reseller in the name), e.g. mp_a1b2c3.... The token is derived from secrets.token_hex(32) and SHA-256 hashed before storage — only shown once on creation.

Token Lifetime

Client tokens have no expiry by default (the expires_at field is NULL unless set). Use DELETE /api/client/api-tokens/{id} to revoke them.

Authentication Methods

# Option A: Bearer Header (Recommended)
Authorization: Bearer mp_YOUR_API_KEY

# Option B: X-API-Key Header
X-API-Key: mp_YOUR_API_KEY

# Option C: Query Parameter
GET /api/client/websites?api_key=mp_YOUR_API_KEY

# Optional: Scope to a specific hosting account (multi-account users)
X-Hosting-Account-ID: 2

Managing Client API Tokens via API

Admin Panel

Admin API

The Admin API is available on port 8001 and is accessible only to authenticated admin accounts. All endpoints are prefixed with /api/admin/. Authenticate using a long-lived API token generated from the Admin panel.

API Key Guide — Admin Panel

How to Generate an Admin API Key

Admin API keys are scoped to the individual admin account that created them. There are two ways to create one:

  • In the UI: Log in to the Admin Panel (port 8001), go to Settings > API Tokens, click Generate Token, enter a name and optional permission scopes.
  • Via API (requires an active admin session or existing admins.manage token): 
    POST /api/admin/api-tokens
Content-Type: application/json
Authorization: Bearer mp_admin_EXISTING_TOKEN

{"name": "CI/CD Pipeline Key", "permissions": ["clients.manage", "hosting.manage"]}
    Response (token is shown only once): 
    {"id": 5, "name": "CI/CD Pipeline Key", "token": "mp_admin_a1b2c3d4...", "permissions": ["clients.manage", "hosting.manage"]}
Requires admins.manage Permission

Creating or deleting Admin API tokens via POST /api/admin/api-tokens requires the acting admin to hold the admins.manage permission (or the wildcard * / all). super_admin accounts always pass this check. system_admin and support_admin roles do not hold this permission by default.

Token Format

Admin tokens are prefixed with mp_admin_ (e.g. mp_admin_a1b2c3...). The prefix is used at authentication time to route the request to the correct token table. The raw hex suffix is SHA-256 hashed before storage — only shown once on creation.

Token Lifetime

Admin tokens have no expiry by default (the expires_at column is NULL unless explicitly set). Revoke with DELETE /api/admin/api-tokens/{id}. last_used_at is updated on every successful request.

Authentication Method

# Bearer header (only supported method for admin tokens)
Authorization: Bearer mp_admin_YOUR_API_KEY

# X-API-Key header also accepted
X-API-Key: mp_admin_YOUR_API_KEY

# Query parameter also accepted
GET /api/admin/dashboard?api_key=mp_admin_YOUR_API_KEY

Permission Scopes (for API Token Access Control)

When creating an Admin API token you can restrict it to a subset of operations by passing a permissions array. The available permission strings are:

PermissionGrants Access ToDefault for Role
* or allFull admin access (wildcard)super_admin
clients.manageCreate, update, delete, impersonate clientssystem_admin
clients.readRead-only access to client datasupport_admin
hosting.manageProvision, suspend, unsuspend, change planssystem_admin
hosting.readRead-only access to hosting accountssupport_admin
dns.manageDNS settings, domain operationssystem_admin
dns.readRead-only DNS datasupport_admin
system.manageStorage, networking, nodes, agent, status pagesystem_admin
admins.manageCreate admins, manage API tokens, manage 2FAsuper_admin only
plans.manageCreate and update hosting plans and reseller planssystem_admin

A token's effective permission is the intersection of the token's own permissions array and the admin's role permissions. Granting ["*"] on a support_admin token still limits it to the role's base permissions.

Reseller Panel

Reseller API

The Reseller API is available on port 8002 (or the configured reseller port) and is accessible to reseller accounts. All endpoints are prefixed with /api/reseller/. Authenticate using a long-lived Reseller API token.

API Key Guide — Reseller Panel

How to Generate a Reseller API Key

Reseller API keys are scoped to the reseller user account. There are two ways to create one:

  • In the UI: Log in to the Reseller Panel (port 8002), go to Settings > API Tokens (shown under the Admins page), click Generate Token, and enter a name.
  • Via API (requires an active reseller session or existing reseller token): 
    POST /api/reseller/api-tokens
Content-Type: application/json
Authorization: Bearer mp_reseller_EXISTING_TOKEN

{"name": "Provisioning Bot", "permissions": ["*"]}
    Response (token is shown only once): 
    {"token_id": 2, "token": "mp_reseller_a1b2c3d4...", "name": "Provisioning Bot"}

Token Format

Reseller tokens are prefixed with mp_reseller_ (e.g. mp_reseller_a1b2c3...). The prefix routes the token to the reseller_api_tokens table at authentication time. The raw 20-byte hex suffix is SHA-256 hashed before storage — only shown once on creation.

Token Lifetime

Reseller tokens are created with an expiry of 365 days from creation (expires_at = now + 31536000). After expiry the server returns 401 reseller_api_token_expired. Generate a new token to replace an expired one.

Authentication Methods

# Bearer header (recommended)
Authorization: Bearer mp_reseller_YOUR_API_KEY

# X-API-Key header also accepted
X-API-Key: mp_reseller_YOUR_API_KEY

# Query parameter also accepted
GET /api/reseller/dashboard?api_key=mp_reseller_YOUR_API_KEY

Permission Scopes

When creating a Reseller API token you can pass a permissions array to narrow its scope. Reseller tokens do not map to named roles — the permissions field is stored as a JSON array and compared directly. Use ["*"] for full reseller access.

Reseller Scope Is Always Enforced

Regardless of the token's permission array, all reseller routes are automatically scoped to resources owned by that reseller. A reseller token can never read or modify another reseller's clients, plans, or accounts. The reseller_id from the authenticated token is injected into every query.

Managing Reseller API Tokens via API

Admin API Fallback

Unmatched reseller routes automatically fall through to the Admin API handler (with the reseller acting as a scoped admin). This means most admin-level read operations are also accessible via the /api/reseller/ prefix.
